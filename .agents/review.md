# 分析与评审原则

- 先核对问题的前提。遇到“更新后会话丢失”，先确认系统、应用版本、服务商，以及用户执行的是隐藏窗口、重载页面还是退出后重启。这些操作走不同的代码路径。
- 区分事实、预测和判断。写明日志或测试直接观察到了什么，哪些原因仍属推测，以及你依据什么建议修改。如果证据与原判断冲突，直接说明并引用对应源码或复现结果。
- 指出会改变结论的遗漏变量、替代解释和成本。例如，新配置可正常恢复会话时，仍需检查旧版本保存的 URL 格式。只用全新配置做测试，会遗漏升级用户。
- 让验证对应结论。例如，声称“修好了 Windows 安装版更新”时，应说明测试使用的安装方式、版本和观察到的更新行为。若只验证了更新器初始化，就按实际验证范围报告。
